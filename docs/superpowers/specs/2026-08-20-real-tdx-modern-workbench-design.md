# 真实通达信现代看板设计规格

日期：2026-08-20  
状态：用户已确认
实现分支：`codex/market-workbench`

## 1. 目标与优先级

本阶段在已经完成的全市场分钟存储、资金分层领域模型和只读 API 基础上，完全重写真实通达信数据链路，并交付可运行的现代看板。实现不复用 `backend/app` 的业务代码，旧 `5178/8765` 服务保持原样作为回退入口。

优先级依次为：

1. 数据准确性、来源可解释和分钟批次完整性。
2. 板块与个股核心资金功能可用。
3. 真实行情、K 线、盘口和回放联动完整。
4. 清爽、专业、默认浅色的视觉体验。

前端不得生成行情、资金、排行或 K 线假数据。真实来源暂时不可用时，页面显示缺口、最后可用时间、来源和错误原因。

## 2. 交付范围

### 2.1 真实数据链路

- 沪深北全部 A 股证券目录。
- 通达信全部行业、概念板块及成分关系。
- 全市场分钟报价、成交额、涨跌幅和资金分层。
- 个股实时行情、价格分时、五档盘口、日 K/分钟 K 和常用技术指标所需原始数据。
- 板块分钟资金由成分股逐层聚合，保留主力、超大单、大单、中单和小单独立口径。
- 交易时段连续调度、节点故障切换、批次幂等提交、重启补采和缺口记录。

### 2.2 查询 API

- 市场概览、全局搜索、板块列表与排行。
- 板块资金曲线、成分股排行和指定分钟快照。
- 个股行情头部、资金曲线、价格分时、K 线、盘口、所属板块。
- 可用交易日、回放快照、共享分钟游标、采集健康和设置。
- 所有行情响应携带交易日、数据分钟、批次 ID、目录版本、覆盖率、来源、质量和最后更新时间。

### 2.3 现代看板

- 板块主工作台。
- 统一个股工作台。
- 全局搜索和自选导航。
- 实时/历史回放模式。
- 默认浅色主题，支持深色切换并持久化用户选择。
- 1920×1080、2K 和常见笔记本宽度完整可用；手机保留核心资金曲线与排行。

## 3. 不在本阶段伪造的能力

- 不用随机数或静态数组冒充真实板块、行情、排行、K 线或盘口。
- 不把估算资金标记为官方资金。
- 不用平滑插值掩盖采集缺口。
- 不在数据不足时承诺开盘以来完整曲线；明确显示可用范围。

## 4. 系统架构

```text
通达信本地目录 C:\new_tdx64       通达信行情节点/资金接口
             │                         │
             └──────────┬──────────────┘
                        ▼
              新 TdxMarketProvider
       ┌──────────┬──────────┬──────────┐
       │目录加载器 │节点连接池 │行情/资金 │
       └──────────┴──────────┴──────────┘
                        │
                        ▼
                 独立 Collector
        目录同步 → 分钟冻结 → 资金聚合 → 原子提交
                        │
           ┌────────────┴────────────┐
           ▼                         ▼
      元数据 SQLite              按日热库 SQLite/WAL
           │                         │
           └────────────┬────────────┘
                        ▼
                    只读 API
                        │
                        ▼
                 Vue 3 现代看板
```

Collector 是行情热库的唯一写入者；API 不连接通达信、不写分钟行情。API 与 Collector 使用独立进程，Collector 离线时 API 继续提供最后一次完整提交的数据。

## 5. 新通达信提供者

### 5.1 模块边界

- `node_pool`：节点探测、延迟排序、连接复用、失败退避和熔断。
- `catalog`：证券、行业、概念和成分关系的完整目录加载及版本生成。
- `quotes`：全市场快照、五档盘口、成交额和涨跌幅。
- `transactions`：逐笔成交/分笔数据获取和分钟归并。
- `fund_flow`：官方资金读取、估算分层、累计/增量转换和质量标记。
- `bars`：日 K、分钟 K、复权信息和历史回补。
- `provider`：实现统一 `MarketDataProvider` 协议并组合以上模块。

这些模块只依赖 `pytdx`、`easy-tdx`、通达信本地文件格式和新领域模型，不导入 `backend/app`。

### 5.2 资金口径

- 每个层级独立保存 `delta`、`cumulative`、`source` 和 `quality`。
- 官方主力值存在时直接保存，不强制等于超大单与大单之和。
- 官方分层不存在时，基于逐笔成交方向与金额阈值估算，并标记为 `estimated`。
- 板块各层级分别汇总成分股同层级值，不跨层重算。
- 收盘校准保留盘中原始值、校准值、算法版本和校准时间。

### 5.3 目录与标识

- 股票统一使用带市场前缀的代码，如 `SH600000`、`SZ000001`、`BJ430047`。
- 板块使用稳定通达信标识并保存行业/概念类型。
- 每次目录同步生成版本；成分股排行必须使用与分钟批次一致的目录版本。
- 目录同步失败时沿用最近成功版本，同时把版本日期和陈旧状态暴露给 API/UI。

## 6. 采集与数据流

### 6.1 启动

1. 校验 `C:\new_tdx64` 和依赖文件。
2. 探测行情节点并建立受控连接池。
3. 同步全市场目录和板块成分。
4. 检查当日最后完整分钟，补采缺失区间。
5. 进入交易时段调度。

### 6.2 每分钟批次

1. 在分钟边界冻结全市场报价快照。
2. 获取官方资金与逐笔估算所需数据。
3. 生成个股五层资金记录。
4. 按目录版本聚合板块五层资金、涨跌幅和成员数量。
5. 在一个事务内替换该分钟股票、板块和状态快照。
6. 状态最后提交；API 仅查询 `complete` 且批次 ID 匹配的数据。

覆盖率低于 99.5% 时显示警告，低于 95% 时显示故障。未恢复记录进入缺口表和补采队列。

### 6.3 回放

- 默认保留最近 30 个交易日，可在设置页修改。
- 实时模式使用最新完整分钟；回放模式固定交易日和分钟游标。
- 资金曲线、板块排行、成分股排行、价格图、K 线指标共享同一游标。
- 历史资金只展示真实已采集或可验证回补的数据；不可获得的区间显示缺口。

## 7. API 设计

现有资金曲线接口继续保留，并新增：

- `GET /api/v1/market/overview`
- `GET /api/v1/search`
- `GET /api/v1/sectors`
- `GET /api/v1/sectors/{sector_id}`
- `GET /api/v1/sectors/{sector_id}/members`
- `GET /api/v1/sectors/{sector_id}/minutes`
- `GET /api/v1/stocks/{symbol}`
- `GET /api/v1/stocks/{symbol}/fund-flow`
- `GET /api/v1/stocks/{symbol}/intraday`
- `GET /api/v1/stocks/{symbol}/bars`
- `GET /api/v1/stocks/{symbol}/order-book`
- `GET /api/v1/stocks/{symbol}/sectors`
- `GET /api/v1/trading-dates`
- `GET /api/v1/replay/snapshot`
- `GET/PUT /api/v1/settings`
- `GET /api/v1/health`

列表接口服务端分页、筛选和排序。板块成员排行按指定分钟在数据库侧计算，前端不得下载全市场后自行排序。

## 8. 前端信息架构

### 8.1 全局框架

- 顶栏：市场状态、全局搜索、交易日、实时/回放模式、覆盖率、延迟、主题。
- 一级入口：板块工作台、个股工作台、自选、数据健康。
- 全局搜索支持代码、股票名、板块名和键盘操作。

### 8.2 板块工作台

- 左栏：行业/概念/自选板块列表和排序控制。
- 主区头部：板块名称、涨跌幅、主力净流入、成交额、上涨/下跌家数和更新时间。
- 核心图：主力净额分时，支持五层资金切换/叠加及价格或涨幅叠加。
- 下区：成分股排行，默认按时间游标对应的主力净流入降序。
- 点击成分股进入个股工作台，并保留返回板块的上下文。

### 8.3 个股工作台

- 行情头部：价格、涨跌、成交量额、换手率、市值和交易状态。
- 核心资金图：与板块一致的五层资金曲线和来源/质量。
- 图表标签：价格分时、日 K、分钟 K、成交量和常用指标。
- 侧栏：五档盘口、资金构成、所属板块和自选操作。
- 所属板块可返回对应板块工作台。

### 8.4 视觉与响应式

- 默认浅色：低饱和灰白背景、清晰边框、紧凑高密度布局，避免大面积刺眼纯白。
- A 股语义：上涨红、下跌绿；资金层级使用固定且色盲友好的专属色。
- 深色主题作为可切换选项并记忆选择。
- 大屏使用完整主从布局；笔记本折叠次要侧栏；手机只保留核心资金图、关键指标和排行。

## 9. 状态与错误处理

- 首次加载显示骨架屏，不用零值冒充数据。
- 空结果区分无成分、未开盘、数据尚未采集和查询条件无匹配。
- Collector 离线时显示最后完整分钟和离线状态，页面继续可用。
- 估算、陈旧、缺口、校准数据使用明确标签和提示。
- WebSocket 后续启用时断线退化为短轮询；轮询失败不清空已有图表。
- API/数据文件损坏返回受控错误，不泄露内部路径和堆栈。

## 10. 测试与验收

### 10.1 数据正确性

- 使用记录型真实响应夹具验证证券、板块、成分、报价、逐笔、资金和 K 线解析。
- 对官方主力、估算分层和板块逐层聚合建立黄金样本。
- 验证累计转增量、午休、停牌、无成交、北交所代码和异常价格。
- 抽样对照通达信客户端同分钟数据，记录允许误差和来源差异。

### 10.2 存储与并发

- 完整分钟原子提交、失败回滚、缩减重采和目录版本一致性。
- WAL 并发读写、API 一致快照和 Collector/API 进程隔离。
- 5,500 股票、全部板块单分钟采集与提交不超过 45 秒。

### 10.3 API 与前端

- 固定 OpenAPI 模型、分页/排序、来源质量和缺口语义。
- 板块→成分股→个股→所属板块闭环。
- 五层资金切换、实时/回放游标、K 线周期和指标联动。
- 浅色/深色、1080p/2K/笔记本关键布局和移动核心视图。
- 前端生产构建通过，主要页面按路由和重型图表动态加载。

## 11. 实施顺序

1. 真实通达信能力探针、连接池和记录型夹具。
2. 证券/板块目录、行情、资金、K 线和盘口提供者。
3. 真实全市场 Collector、连续调度、补采和健康状态。
4. 板块/个股/搜索/排行/回放 API。
5. 板块资金工作台和成分股闭环。
6. 个股行情、资金、K 线、盘口和所属板块闭环。
7. 历史回放、设置、响应式和主题完善。
8. 全链路真实数据验收，在独立端口运行展示。

## 12. 运行隔离

- 旧服务继续使用 `5178/8765`，开发过程中不停止、不重启、不改配置。
- 新系统使用独立数据目录和备用端口；建议前端 `5180`、API `8877`。
- 新系统验收通过并获得用户确认前，不替换旧启动脚本。
